    Understanding Cloud Computing Concepts

    ทำความเข้าใจแนวคิด Cloud Computing

    สรุปภาษาไทยแบบเจาะลึก ครอบคลุมนิยาม คุณลักษณะ รูปแบบ โมเดลบริการ และความรับผิดชอบร่วมของ Cloud Computing ตามแนวข้อสอบ (ISC)² CCSP

    แก่นแท้ของ Cloud รูปแบบของ Cloud โมเดลบริการ Shared Responsibility Reference Architecture Building Block Tech ผลกระทบต่อเทคโนโลยี ข้อพิจารณาร่วม เจาะลึกเพิ่มเติม Exam Tips ทบทวนคำศัพท์ สรุป & Goals คิดแบบผู้ออกข้อสอบ
    01

    แก่นแท้ของ Cloud Computing

    NIST 5 Characteristics

    Cloud computing คือการนำ ทรัพยากรคอมพิวเตอร์ของผู้อื่น (ผู้ให้บริการ หรือ Cloud Service Provider — CSP) มาใช้ประมวลผลงานของเรา สิ่งที่ทำให้ cloud computing ยุคปัจจุบันต่างจาก web hosting แบบเดิม คือ CSP วางตัวเป็นธุรกิจที่ขาย "บริการคอมพิวเตอร์" แบบ self-service ตามความต้องการ ไม่ใช่แค่ให้เช่าเซิร์ฟเวอร์ตายตัว

    NIST นิยามคุณลักษณะหลักของ cloud computing ไว้ 5 ข้อ ซึ่งเป็นแกนของเนื้อหาตลอดทั้งเล่ม:

    01

    On-demand self-service

    สั่งสร้าง/ยกเลิกทรัพยากรได้เองทันทีผ่านระบบ โดยไม่ต้องรอเจ้าหน้าที่ดำเนินการ

    02

    Broad network access

    เข้าถึงทรัพยากรผ่านอินเทอร์เน็ตได้ทุกที่ ต่างจาก on-premise ที่ต้องซื้อ/เดินสายเข้าถึงอุปกรณ์จริง

    03

    Rapid elasticity

    ขยายหรือหดขนาดทรัพยากรได้อย่างรวดเร็วตามโหลดจริง แทบจะทันที

    04

    Measured service

    วัดปริมาณการใช้งานต่อเนื่อง และจ่ายเงินตามที่ใช้จริง (pay-per-use)

    05

    Resource pooling

    CSP รวมทรัพยากรเป็น pool กลาง แล้วจัดสรรให้ลูกค้าแบบ on-demand ตามความต้องการ

    ทำไม rapid elasticity ถึงทำได้ยากใน on-premise

    ตัวอย่าง: แอปพลิเคชันภายในที่ใช้เฉพาะเวลาทำงาน 9.00–17.00 น. บน cloud คุณปิดเซิร์ฟเวอร์นอกเวลาทำงานได้ทันที และจ่ายเฉพาะ 8 ชั่วโมงที่ใช้จริง แต่ถ้าเป็น on-premise แม้จะปิดเครื่อง ก็ยังต้องแบกต้นทุนที่จ่ายไปแล้วสำหรับฮาร์ดแวร์ อีกทั้งถ้าเครื่องนั้นถูก virtualize ใช้ร่วมกับงานอื่น การปิดเครื่องอาจกระทบแอปอื่นด้วย

    Resource pooling ทำงานอย่างไร

    เมื่อองค์กรหนึ่งคืนทรัพยากรกลับสู่ pool (เช่น ปิดเซิร์ฟเวอร์นอกเวลางาน) capacity ส่วนนั้นจะพร้อมให้ลูกค้ารายอื่นใช้ทันที การทำเช่นนี้ช่วยให้ CSP ควบคุมต้นทุนฮาร์ดแวร์โดยรวมได้ แต่ก็มีความเสี่ยงสองด้าน: หากลูกค้าต้องการพร้อมกันมากเกิน CSP อาจขาด capacity จนเกิด service outage และหากจัดสรรไว้เกินความต้องการจริง CSP ก็แบกต้นทุนที่ไม่คุ้มทุน หลาย CSP จึงเสนอส่วนลดหากลูกค้า commit ใช้งานขั้นต่ำล่วงหน้า

    EXAM TIP

    Resource pooling คือความเสี่ยงด้านความปลอดภัยที่สำคัญของ cloud เพราะหมายถึงการ "ใช้ฮาร์ดแวร์ร่วมกับองค์กรอื่น" (multi-tenancy)

    02

    รูปแบบของ Cloud

    Deployment Models

    Cloud ไม่ได้มีแค่รูปแบบเดียว องค์กรเลือกได้ว่าจะประมวลผล workload ที่ scope ไหน แชร์กับใคร และในระดับความปลอดภัย/ต้นทุนเท่าใด

    Public cloud

    CSP ให้บริการแก่ใครก็ได้ที่ต้องการซื้อ ข้อดีคือ self-service ที่ดีเยี่ยม แต่เพราะใช้ทรัพยากรร่วมกับลูกค้ารายอื่น จึงมีความเสี่ยงจาก "เพื่อนบ้าน" เช่น หากผู้โจมตีสามารถ break out จาก virtual machine ของลูกค้ารายอื่นที่อยู่บนเซิร์ฟเวอร์เดียวกัน ก็อาจกระทบ availability ของเซิร์ฟเวอร์นั้นโดยรวมได้

    Private cloud

    ฮาร์ดแวร์/โครงสร้างพื้นฐานถูกสงวนไว้เฉพาะลูกค้ารายเดียว หรือองค์กรเป็นเจ้าของและดูแลเอง ปลอดภัยกว่าแต่มีต้นทุนสูงกว่า และหากดูแลเอง ก็ต้องมีความรู้ด้านการออกแบบและปฏิบัติการที่ปลอดภัยด้วยตนเอง

    Hybrid cloud

    ผสม private และ public cloud เข้าด้วยกัน ช่วยให้เลือกได้ว่างานที่ sensitive ควรอยู่ใน private ส่วนงานทั่วไปอยู่ใน public มักเชื่อมต่อกันด้วย VPN หรือ leased line

    Community cloud

    หลายองค์กรใช้สภาพแวดล้อมร่วมกัน เช่น กลุ่มมหาวิทยาลัยที่ทำวิจัยร่วมกัน ความเสี่ยงคือมาตรฐานความปลอดภัยของแต่ละองค์กรต้องสอดคล้องกัน — หากมหาวิทยาลัย A ใช้แค่ password ขณะที่ B ใช้ MFA ผู้โจมตีมักเจาะผ่านบัญชีของ A ได้ง่ายกว่า จึงต้องมี security baseline ร่วมกัน

    Multi-cloud

    ใช้หลาย cloud environment พร้อมกัน (เช่น Azure + AWS) เพื่อดึงจุดแข็งเฉพาะของแต่ละเจ้า แต่เหตุผลสำคัญที่หลายองค์กรเลือกใช้คือป้องกัน vendor lock-in — การพึ่งพา vendor รายเดียวจนแทบเปลี่ยนไม่ได้ multi-cloud ช่วยสลับไปใช้อีกเจ้าได้หากซิงก์ข้อมูลไว้ดี (แต่ไม่ใช่ multi-cloud ทุกแบบจะแก้ vendor lock-in ได้)

    รูปแบบเหล่านี้ผสมกันได้ เช่น hybrid community multi-cloud — data center ของมหาวิทยาลัย + AWS + Azure ที่หลายมหาวิทยาลัยใช้ร่วมกัน

    EXAM TIP

    ข้อสอบมักถือว่า private cloud ปลอดภัยกว่า public cloud เสมอ และมองว่า multi-cloud คือมาตรการป้องกัน vendor lock-in

    นอกจาก 3 โมเดลหลักแล้ว ในตลาดยังมีคำเรียกเช่น Identity as a Service, Security as a Service, SOC as a Service ซึ่งส่วนใหญ่เป็นเพียง SaaS ที่ทำหน้าที่เฉพาะทาง

    EXAM TIP

    IaaS, PaaS, SaaS คือโมเดลบริการ "ทางการ" เพียง 3 แบบที่ข้อสอบ CCSP พิจารณา

    ทำไม CSP รับผิดชอบ data center เสมอ

    เพราะ CSP ให้บริการโครงสร้างพื้นฐานผ่าน data center ของตัวเอง โดยไม่เคยให้ลูกค้าเข้าถึง data center จริง องค์กรขนาดเล็กจึงได้ประโยชน์มหาศาล เพราะไม่ต้องแบกต้นทุนสร้าง/ดูแล data center เอง

    ทำไม consumer รับผิดชอบข้อมูลเสมอ

    เพราะเหตุผลด้านความปลอดภัย — องค์กรไม่ต้องการให้ vendor เข้าถึงข้อมูลของตนได้ CSP หลายเจ้าจึงออกแบบให้เข้าไปแตะข้อมูลลูกค้าโดยตรงแทบไม่ได้ เช่นการเข้ารหัสด้วย Customer Managed Key (CMK) หรือ Customer Provided Key (CPK) ที่ CSP ไม่รู้กุญแจ จึงถอดรหัสเองไม่ได้

    ทำไมบางแถวถึง "รับผิดชอบร่วมกัน"

    ตัวอย่างเช่นใน PaaS: หาก CSP ให้บริการ managed database ลูกค้าไม่ต้องดูแล network หรือ database server แต่ยังต้องรับผิดชอบว่าใครเข้าถึง database ได้บ้าง ส่วน CSP ต้องรับผิดชอบให้บริการพร้อมใช้งานเสมอ เช่น ป้องกัน Denial of Service (DoS)

    EXAM TIP

    ฝึกจับคู่ CSP รายจริงกับบริการหนึ่ง แล้วลองระบุว่าใครรับผิดชอบ control อะไร จากนั้นตรวจคำตอบกับ Shared Responsibility Model ที่ CSP รายนั้นเผยแพร่จริง

    05

    Cloud Reference Architecture

    NIST SP 500-292

    NIST กำหนดผู้มีส่วนเกี่ยวข้องหลักในระบบนิเวศ cloud ไว้ 4 ฝ่าย ความเข้าใจบทบาทของแต่ละฝ่ายเป็นหัวใจของโดเมนนี้ในข้อสอบ

    Cloud Consumer

    ผู้ใช้บริการ ซื้อบริการตรงจาก CSP หรือผ่าน cloud broker ก็ได้

    Cloud Provider (CSP)

    ผู้ให้บริการ ดูแล service orchestration, resource abstraction และ physical resource layer

    Cloud Auditor

    ตรวจสอบความปลอดภัย ความเป็นส่วนตัว และประสิทธิภาพของ cloud

    Cloud Broker

    ตัวกลางที่ช่วยลูกค้าเลือกซื้อบริการ อาจรวมบริการหลายเจ้าหรือช่วย implement/operate ให้ลูกค้า

    ประเด็นสำคัญที่ข้อสอบชอบถามคือ cloud consumer ตรวจสอบโครงสร้างพื้นฐานของ CSP เองโดยตรงแทบไม่ได้ จึงต้องพึ่ง cloud auditor เพื่อขอใบรับรองมาตรฐานสากล เช่น ISO 27001 มาเป็นหลักฐาน

    EXAM TIP

    ต้องเข้าใจว่า cloud consumer มีความสามารถจำกัดมากในการตรวจสอบบริการที่ CSP มอบให้

    06

    Building Block Technologies

    5 เสาหลัก

    ทุก cloud environment ถูกประกอบขึ้นจากเทคโนโลยีพื้นฐาน 5 กลุ่ม: Networking, Storage, Virtualization, Databases และ Orchestration

    CSP ต้องรองรับลูกค้าหลายรายพร้อมกัน (multi-tenancy) ผ่านอินเทอร์เน็ต (broad access) ตลอดเวลา จึงใช้ virtual network / network overlay ซ้อนทับบนเครือข่ายจริง (underlay) เพื่อแยก traffic ของลูกค้าแต่ละรายออกจากกันอย่างสมบูรณ์

    • Virtual network (subnet) — เชื่อมระบบ/บริการของลูกค้าเข้าด้วยกันเหมือนเครือข่ายจริง
    • Virtual firewall / ACL — กำหนดสิทธิ์เข้า-ออกตาม IP หรือข้อมูลอุปกรณ์
    • Security groups — deny-by-default ผูกกับ instance/identity ต่างจาก ACL ที่ผูกกับ subnet
    • WAF — อ่านเนื้อหา request แบบ context-aware เช่น ตรวจจับ SQL injection
    • VNI — network adapter เสมือนที่ผูก security control ไว้ได้
    • Direct connection — เชื่อม on-premise กับ cloud ผ่าน VPN หรือ leased line
    • Network peering — เชื่อม virtual network หลายวงเข้าด้วยกัน

    Virtualization คือสิ่งที่ทำให้ rapid elasticity และ on-demand self-service เป็นไปได้จริง

    • Type-1 (bare-metal) — hypervisor รันตรงบนฮาร์ดแวร์จริง หาก hypervisor ถูกเจาะ VM ทั้งหมดเสี่ยงไปด้วย
    • Type-2 (hosted) — hypervisor ทับบน OS ปกติ ประสิทธิภาพต่ำกว่า
    EXAM TIP

    (ISC)² มองว่า Type-1 ปลอดภัยและมีประสิทธิภาพกว่า Type-2

    ลูกค้าเลือกโฮสต์ฐานข้อมูลบน VM เอง หรือใช้ managed database ที่ CSP ดูแลโครงสร้างพื้นฐานและตัวเซิร์ฟเวอร์ทั้งหมด รองรับ high availability และเปิด encryption ได้ในคลิกเดียว

    EXAM TIP

    (ISC)² มองว่า managed database ปลอดภัยกว่า self-hosted database

    กลไกที่ใช้สร้าง instance, storage, เครือข่าย และแอปใหม่แบบอัตโนมัติ ทุก CSP ใช้ Infrastructure as Code (IaC) ผ่าน template ที่กำหนดล่วงหน้า ช่วยลด manual access เข้า production ซึ่งเพิ่มความปลอดภัยไปในตัว

    07

    ผลกระทบของ Cloud ต่อเทคโนโลยีอื่น

    Beyond infra

    cloud computing ทำให้ "การประมวลผลที่เคยเป็นไปไม่ได้ กลายเป็นไปได้" และผลักดันเทคโนโลยีหลายกลุ่มให้เติบโตเร็วขึ้น

    AI & Data Science

    การประมวลผลข้อมูลมหาศาลแบบเรียลไทม์และการฝึก ML ทำได้จริงเพราะพลังประมวลผลของ cloud

    Quantum Computing

    qubit เก็บ 0 และ 1 พร้อมกัน เพิ่มความเร็วมหาศาล — เสี่ยงถอดรหัส encryption ปัจจุบันได้เร็วขึ้นมาก

    Internet of Things

    อุปกรณ์ขนาดเล็กส่งข้อมูลขึ้น cloud ให้ประมวลผลแทน ลดต้นทุนฮาร์ดแวร์

    DevSecOps

    ฝังความปลอดภัยเข้าไปในทีมพัฒนา เพราะ cloud ทำให้ทีมสร้างทั้งโครงสร้างพื้นฐานและแอปเป็นโค้ดได้เอง

    Containers

    VM ขนาดเล็กที่บรรจุเฉพาะซอฟต์แวร์ที่จำเป็น พกพาได้ข้ามระบบปฏิบัติการ

    EXAM TIP

    ทบทวนเทคโนโลยีทั้งหมดในหัวข้อนี้ให้คุ้นเคย ข้อสอบมักครอบคลุมทุกหัวข้อที่กล่าวถึงในส่วนนี้

    09

    เจาะลึกเพิ่มเติม

    คำว่า up the stack และ down the stack ที่ยืมมาจากบริบทของ TCP/IP ถูกนำมาใช้อธิบายความสัมพันธ์ของ IaaS, PaaS และ SaaS ที่ซ้อนทับกันเป็นชั้น โดย IaaS อยู่ล่างสุดของ stack ไล่ขึ้นไปเป็น PaaS แล้วจึงเป็น SaaS อยู่บนสุด ยิ่งขึ้นไปสูงเท่าไร ความรับผิดชอบด้านการจัดการโครงสร้างพื้นฐานก็ยิ่งเปลี่ยนจากลูกค้าไปเป็นของผู้ให้บริการมากขึ้นเท่านั้น

    แม้ serverless computing และ Function as a Service (FaaS) จะดูคล้าย PaaS ตรงที่ซ่อนการจัดการโครงสร้างพื้นฐานจากนักพัฒนา แต่ PaaS ยังต้องมีการจัดการเซิร์ฟเวอร์และการปรับขยายอยู่เบื้องหลัง ในขณะที่ FaaS ไม่จำเป็นต้องมีกระบวนการเซิร์ฟเวอร์ทำงานตลอดเวลา โค้ดจะถูกเรียกทำงานเฉพาะเมื่อมีเหตุการณ์ (event) มาทริกเกอร์ฟังก์ชันเท่านั้น

    FaaS เริ่มเป็นที่รู้จักในวงกว้างจากการเปิดตัว AWS Lambda ในปี 2014 หลังจากนั้น Microsoft Azure และ Google Cloud Platform จึงตามมาด้วยบริการ serverless ของตนเอง

    หน่วยงานภาครัฐมักมองหาคลาวด์ที่มีชื่อเรียกว่า GovCloud เพื่อความมั่นใจว่ามีเฉพาะข้อมูลของหน่วยงานรัฐเท่านั้นที่อยู่ในคลาวด์นั้น แม้คำว่า GovCloud จะมีนัยทางการตลาดอยู่บ้าง แต่ก็สะท้อนเจตนารมณ์ของโมเดล community cloud ได้ชัดเจน คือการรวมกลุ่มผู้ใช้ที่มีข้อกำหนดด้านความปลอดภัยหรือการปฏิบัติตามกฎระเบียบที่เหมือนหรือคล้ายกันไว้ในคลาวด์เดียวกัน

    Hybrid cloud ทุกแบบถือเป็น multi-cloud โดยธรรมชาติ เพราะเป็นการผสมผสานคลาวด์อย่างน้อยสองประเภทเข้าด้วยกัน แต่ไม่ใช่ multi-cloud ทุกแบบที่เป็น hybrid cloud เพราะ multi-cloud หมายถึงการใช้ผู้ให้บริการคลาวด์หลายรายเท่านั้น ซึ่งอาจเป็น public cloud ล้วนๆ จากหลายเจ้าโดยไม่มีส่วนของ private หรือ on-premise เลยก็ได้

    หนังสือเล่มนี้ใช้ ISO/IEC 17788 เป็นฐานสำหรับนิยามศัพท์พื้นฐาน เช่น cloud service, tenant, resource pooling แยกจาก NIST SP 800-145 ที่ให้นิยามคลาวด์อย่างเป็นทางการและเป็นที่นิยมมากกว่าในข้อสอบ

    reversibility ตาม ISO/IEC 17788 ไม่ได้หมายถึงเพียงการลบข้อมูลทิ้ง แต่หมายถึงความสามารถของลูกค้าที่จะดึงข้อมูลและแอปพลิเคชันทั้งหมดออกจากผู้ให้บริการคลาวด์ และลบข้อมูลออกจากสิ่งแวดล้อมนั้นอย่างสมบูรณ์ พร้อมย้ายไปยังสิ่งแวดล้อมใหม่โดยกระทบต่อการดำเนินงานน้อยที่สุด

    ISO/IEC 17789:2014 จัดกลุ่มบทบาท cloud auditor, cloud service broker และ cloud service customer ไว้ภายใต้ร่มของ 'cloud service partner' ซึ่งเป็นรายละเอียดที่มักถูกลืมเพราะหลายคนคิดว่า auditor เป็นบทบาทอิสระ

    ฝั่งผู้ให้บริการมีบทบาทเฉพาะทางที่น่าสนใจ เช่น inter-cloud provider ซึ่งรับผิดชอบการเชื่อมต่อกับผู้ให้บริการคลาวด์รายอื่นและบริหารระบบสหพันธ์ (federation) และ cloud service security and risk manager ที่ดูแลความสอดคล้องด้านความปลอดภัยโดยเฉพาะ

    ก่อนจะพูดถึง IaaS/PaaS/SaaS หนังสือแยกแนวคิด 'cloud service capability' ออกเป็นสามระดับคือ infrastructure, platform และ software capability ซึ่งเป็นพื้นฐานที่ทำให้เกิดหมวดบริการทั้งสามชนิด การเข้าใจ capability ก่อน category ช่วยอธิบายว่าทำไมขอบเขตความรับผิดชอบของลูกค้าค่อย ๆ ลดลงตามลำดับ IaaS > PaaS > SaaS

    หนึ่งในประโยชน์ของ IaaS ที่มักไม่ถูกกล่าวถึงคือศักยภาพด้าน 'green data center' ผู้ให้บริการคลาวด์รายใหญ่มักลงทุนสร้างศูนย์ข้อมูลที่มีประสิทธิภาพด้านพลังงานและการระบายความร้อนสูงกว่าที่องค์กรทั่วไปจะทำได้เอง เพราะได้ประโยชน์จาก economies of scale

    ใน PaaS ผู้ให้บริการรับผิดชอบไลเซนส์ของระบบปฏิบัติการและแพลตฟอร์ม ส่วนใน SaaS ผู้ให้บริการรับผิดชอบไลเซนส์ของซอฟต์แวร์ทั้งหมด ทำให้ลูกค้าเพียง 'เช่าใช้' ตามการบริโภคทรัพยากร ข้อดีแอบแฝงคือผู้ให้บริการขนาดใหญ่สามารถต่อรองไลเซนส์แบบ bulk ได้ถูกกว่าที่บริษัทเดี่ยวจะทำได้เอง

    นอกจาก IaaS/PaaS/SaaS ยังมีหมวดบริการเกิดใหม่ที่มีชื่อเฉพาะ เช่น CaaS (Compute as a Service) สำหรับ serverless ที่จ่ายตามรอบการประมวลผลจริง DBaaS ที่ผู้ให้บริการติดตั้งและดูแลฐานข้อมูลทั้งหมด DaaS สำหรับ virtual desktop บนคลาวด์ และ IDaaS สำหรับ IAM/SSO แบบ subscription

    ยังมี NaaS สำหรับเครือข่ายเสมือนที่ปรับค่าคอนฟิกด้วยซอฟต์แวร์แทนสายเคเบิลจริง และ STaaS ที่คิดค่าใช้จ่ายตามปริมาณพื้นที่จัดเก็บที่ใช้จริงหรือที่สำรองไว้

    Governance (การกำกับดูแลระบบและข้อมูล) เป็นความรับผิดชอบของลูกค้าคลาวด์เสมอไม่ว่าจะใช้โมเดลคลาวด์แบบใด เป็นหนึ่งใน anchor point ไม่กี่จุดที่ไม่เคยถูกโอนให้ผู้ให้บริการ (อีกจุดคือ physical security ที่เป็นของผู้ให้บริการเสมอ)

    EXAMINER

    นิยาม NIST ของ IaaS/PaaS/SaaS ต้องอ่านทุกคำอย่างละเอียด เพราะตัวลวงมักสลับคำว่า 'consumer' กับ 'provider' เพียงคำเดียวในประโยคเดียวกัน (เช่น เปลี่ยนจาก 'consumer สามารถ deploy ซอฟต์แวร์' เป็น 'provider สามารถ deploy') อย่าจับใจความคร่าวๆ ต้องอ่านทีละคำ
