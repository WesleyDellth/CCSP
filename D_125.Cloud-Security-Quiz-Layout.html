Q1 · Domain 1 · Cloud Concepts, Architecture and Design

An attacker generates a sustained flood of synthetic API requests against a cloud-hosted application to deliberately trigger auto-scaling events and inflate the target organization's cloud usage charges. The security team wants to identify the earliest indicator of this attack. What is the MOST effective first-line detection mechanism for this type of abuse?

ผู้โจมตีส่ง synthetic API request จำนวนมหาศาลอย่างต่อเนื่องไปยังแอปพลิเคชันที่โฮสต์บนคลาวด์ เพื่อจงใจกระตุ้นเหตุการณ์ auto-scaling และทำให้ค่าใช้จ่ายการใช้งานคลาวด์ขององค์กรเป้าหมายพุ่งสูง ทีมความมั่นคงปลอดภัยต้องการระบุตัวบ่งชี้แรกสุดของการโจมตีนี้ กลไกการตรวจจับด่านแรกที่มีประสิทธิผลที่สุด (MOST effective) สำหรับการใช้ในทางที่ผิดลักษณะนี้คืออะไร

Explanation / คำอธิบาย

Incorrect. Suggested answer: B

Measured service tracks every unit of compute, storage, and network consumption, making billing and usage monitoring the earliest indicator of cost-based attacks exploiting auto-scaling. This attack uses external synthetic traffic and requires no unauthorized account access, so IAM log review would not surface it. Network firewalls and IDS may reduce traffic volume but are not the earliest detection mechanism for cost-based abuse. Disabling rapid elasticity removes a core cloud capability and provides no detection visibility. It is an operational constraint, not a detection control.

Measured service ติดตามการใช้ compute, storage และ network ทุกหน่วย การเฝ้าติดตามการเรียกเก็บเงินและการใช้งานจึงเป็นตัวบ่งชี้แรกสุดของการโจมตีที่มุ่งสร้างต้นทุนโดยใช้ประโยชน์จาก auto-scaling การโจมตีนี้ใช้ทราฟฟิกสังเคราะห์จากภายนอกและไม่ต้องเข้าถึงบัญชีโดยไม่ได้รับอนุญาต การตรวจ IAM log จึงไม่พบสิ่งใด Firewall และ IDS อาจลดปริมาณทราฟฟิกได้ แต่ไม่ใช่กลไกตรวจจับที่เร็วที่สุดสำหรับการใช้ในทางที่ผิดด้านต้นทุน การปิด rapid elasticity ตัดความสามารถหลักของคลาวด์และไม่ทำให้มองเห็นการโจมตี เป็นเพียงข้อจำกัดเชิงปฏิบัติการ ไม่ใช่มาตรการตรวจจับ
